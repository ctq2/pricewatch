# PriceWatch · 价格行情监控看板

面向鞋类货号的**跨平台比价与自动调价决策**看板。零依赖、零构建，双击即开。

## 解决什么问题

做多平台转卖时，有三个问题靠人肉盯不住：

1. **同一货号在 KREAM 和得物的到手价不一样。** 两个平台抽成不同（KREAM 5% / 得物 7.5%），
   标价高的那个平台未必是赚得多的那个。
2. **利润要扣完才知道。** 售价 → 扣平台抽成 → 扣瑕疵损耗 → 减成本，才是真实毛利。
   心算很容易把"看起来赚 200"算成"实际赚 80"。
3. **竞品砸价时该不该跟？** 跟了可能跌破利润线，不跟可能一单不出。
   判断依据是"跟完之后利润率还够不够"，而不是"对方降了多少"。

## 自动决策逻辑

系统对每个货号给出四种结论之一，判定顺序即优先级：

| 结论 | 触发条件 |
|---|---|
| **建议下架** | 价格倒挂（售价低于成本），或利润率低于目标且无跟价空间 |
| **建议调价** | 当前达标，竞品更低，且跟价后**仍然达标** |
| **维持** | 当前达标，无需调价；或竞品更低但跟价后会跌破目标（**不跟价**） |
| **建议上架** | 达标但当前未上架 |

第二条与第三条的边界是这个看板的核心：

```
竞品从 ¥800 降到 ¥620，成本 ¥500，目标利润率 10%
  跟到 620：620 × 0.95 = 589 → 利润率 17.8% ≥ 10%  → 跟（建议调价）
竞品从 ¥800 降到 ¥600，成本 ¥500，目标利润率 30%
  跟到 600：600 × 0.95 = 570 → 利润率 14.0% < 30%  → 不跟（维持原价）
```

**「利润不足就无脑跟价」是这类系统最常见的坑**——跟到最后每单都在亏，
而且因为单量上去了，亏损被放大。

## 利润公式

```
到手价 = 售价 × (1 - 平台费率) × (1 - 瑕疵损耗率)
单件毛利 = 到手价 - 成本
利润率 = 单件毛利 / 成本

反推达标售价：
  售价 = 成本 × (1 + 目标利润率) / ((1 - 费率) × (1 - 损耗率))
```

`建议售价` 与 `利润率` 互为逆运算，测试里专门钉了这条往返一致性 ——
两者公式一旦不一致，自动定价会稳定地报出一个永远达不到的目标。

## 设计说明

参考 Apple HIG 的几条具体做法：

- **字体**：优先系统字体栈（SF Pro / 苹方），不引入 Web 字体，首屏零等待
- **层次**：卡片用半透明 + `backdrop-filter` 制造层叠感，而不是靠边框堆叠
- **动效**：`cubic-bezier(0.34, 1.32, 0.64, 1)` 的轻微过冲，让交互有"重量"
- **数字**：全部使用 `font-variant-numeric: tabular-nums`，刷新时数字不跳动
- **克制**：只有一个强调色（蓝），其余颜色都承载语义（绿=达标、红=亏损、橙=临界）
- **无障碍**：`prefers-reduced-motion` 降级、`prefers-color-scheme` 明暗两套、键盘焦点环

## 接入真实数据

`src/data.js` 的 `buildMarket()` 是唯一的数据入口。替换成接口返回值即可，
上层只依赖结构（`{ id, name, cost, sizes[], history: { KREAM: [{day, price}] } }`），
不关心数据从哪来。真实接入时还需要补：定时轮询、接口调用日志、Excel 批量导入导出。
